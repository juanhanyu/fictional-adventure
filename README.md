# 转生千金～到了异世界就要悠闲地生活

一款中文 Galgame / 视觉小说网页游戏。玩家以希尔维亚的视角经历转生、童年、魔法学院与旅途；游戏结合季度推进、场景探索、角色互动、养成、CG 与背景音乐演出。

项目是**纯静态前端**：无需后端或构建步骤。

## 运行与测试

### 本地预览

使用任意静态文件服务器在仓库根目录启动预览：

```bash
python3 -m http.server 8000
```

随后访问 `http://localhost:8000`。

### 自动化测试

```bash
cd tests
npm ci       # 首次安装或依赖变更后执行
npm test
```

测试基于 jsdom，覆盖剧情数据、门控流程、面板一致性、BGM、CG、立绘年龄档位、快捷键与舞台逻辑。所有改动完成后都应运行测试；新增剧情、背景、音乐或立绘时尤其如此。

## 项目结构

| 路径 | 职责 |
| --- | --- |
| `index.html` | 标题页、HUD、游戏舞台、弹窗与演出层的 DOM 结构 |
| `game.js` | 游戏引擎：状态、时间、探索、门控、存档、战斗、BGM、CG 与立绘舞台 |
| `js/story.js` | 剧情章节、场景与对话数据 |
| `style.css` | 背景、立绘、对话框、布局与动效样式 |
| `assets/bg/` | 场景背景图 |
| `assets/cg/` | CG 演出图 |
| `assets/portraits/` | 角色立绘 |
| `Music/` | 背景音乐文件 |
| `tests/` | 自动化测试与测试运行器 |

## 内容架构

- 剧情数据位于 `js/story.js` 的 `SCENES` 中；`game.js` 启动时通过 `mergeStory()` 合并同名场景，**同名场景以 `js/story.js` 为准**。
- 剧情文本使用中文。源码中的换行写作 `\n`，运行时由 `escapeText()` 转成 `<br>`。
- 季度推进时，`checkStoryGates()` 依据 `dateAtLeast()`、阶段与标记生成剧情队列；多个到期场景通过 `runSceneQueue()` 连续播放。
- 游戏状态、角色关系、背包、图鉴与待播剧情会自动保存。剧情完成前不得提前写入完成门控标记。

### 剧情行辅助函数

| 函数 | 用途 |
| --- | --- |
| `T(text, extra)` | 旁白 |
| `say(ch, text, extra)` | 单人台词；角色名由 `CHARS[ch].short` 提供 |
| `P(ids)` | 立绘列表；支持 `left`、`center`、`right`、`fourth` 槽位 |
| `N(text, ids, extra)` | 带焦点立绘的旁白；单个角色会替换舞台 |
| `DUO(a, b, speaker, text, extra)` | 双人对话；双方同时在场，当前说话者高亮 |

每个剧情行还可携带 `bg`、`loc`、`bgm`、`flag`、`know`、`love`、`sfx`、`do`、`freeRoam`、`card`、`pickTier` 等字段。

## 剧情制作规范

### 原作与叙事

1. 剧情须忠实对应原著的角色、事件、设定与时间线；不擅自添加或篡改原著不存在的台词和事件。
2. 每个对话框只呈现一句台词。过长台词、连续反应与时间流逝应拆成多个剧情行。
3. 不把有节奏的对话、内心戏或小插曲压缩成概述；通过逐句点击保留情绪递进与人物性格。
4. 非希尔维亚视角的章节使用 `pov:'<角色 id>'`，以隐藏 HUD 并强化视角演出。
5. 切换到新时间、地点或事件时，要清空旧立绘（`portraits: []`）后再建立新舞台。

### 场景与舞台

1. 每个剧情段都应设置合理的 `bg` 和合法的 `loc`；切换场景时二者一并更新。
2. `bg` 必须包含在 `style.css` 定义过的 `bg-img-*` 背景图类；只有色调类会导致背景图缺失。
3. 有对话的双方必须同时显示立绘。当前发言者设为 `active`，其他在场角色置暗而不应无故消失。
4. 角色站位必须稳定：主角在场时主角固定左侧；主角不在场时，段落主导者固定左侧。切换说话者只改变高亮，不能左右互换。
5. 对话中的旁白应保留在场角色并全部置暗；短暂插话只替换对应位置，不能让主导者来回移动。
6. 单角色 `N()` 会替换整个舞台。多人对话中需要特写时，使用两个角色的 `N()` 参数以保留主导者。

## 资源与立绘规范

### 背景与地点

- `loc` 必须是 `LOCS` 中存在的 key，否则地点栏会显示「──」。
- 课堂使用 `water_class` 与 `bg-img-classroom bg-school`；训练与比试使用 `training_field` 与 `bg-img-training bg-plain`。
- 新增背景类时，同时在 `BG_CLASS_TYPE` 中登记对应 BGM 类型。

### 立绘

- 文件放在 `assets/portraits/`。
- 三姐妹命名：`<id>_<阶段>_<表情>.png`。
- 年龄阶段：`child`（0–5）、`young`（6–11）、`teenage`（12+）。姐姐贝阿特丽丝按主角年龄 +2、妹妹爱丽丝按主角年龄 -2 计算。
- 新角色或表情需同步登记 `PORTRAIT_FILES`、`CHARS` 与 `CSS_CHARS`，否则会回退为 CSS 占位立绘。
- 表情按角色性格使用：希尔维亚日常使用 `normal`、明显微笑使用 `smile`、真正严肃才使用 `serious`；贝阿特丽丝的 `normal` 已是日常开朗状态；爱丽丝的 `happy` 是含蓄微笑。
- 没有制作的表情不可用其他表情硬替代。剧情确实需要时，应先补齐对应立绘资源。
- 法神（`fashen`）只在剧本明确需要时出现，不作为学院自由探索的随机角色。

## BGM 规范

音乐文件位于 `Music/`。`game.js` 的 `BGM_FILES` 管理曲目路径，`BGM_GROUPS` 管理情绪类型与轮换顺序。

1. **每个 `SCENES` 场景都必须显式设置 `bgm`**，不能依赖背景推断。合法类型：`battle`、`cheerful`、`academy`、`peaceful`、`relax`、`sacred`、`sad`、`emotional`、`comedy_fast`、`comedy_medium`、`romantic`、`upset`。
2. 剧情场景由 `runScene()` / `stepChain()` 强制播放场景 BGM；自由探索才按背景通过 `BG_CLASS_TYPE` 推断音乐。
3. 同类型曲目按组轮换；同类型切换地点不得重开音乐，跨类型时才淡出并切曲。
4. `comedy_medium` 用于节奏连贯但不急促的日常闹剧；`comedy_fast` 用于追赶、仓皇逃窜等急促喜剧段落。
5. 新增曲目必须同时加入 `Music/`、`BGM_FILES` 与对应 `BGM_GROUPS`，且文件路径真实存在。
6. 特殊背景映射：`bg-battle` → `battle`、`bg-pick` → `sacred`、`bg-duel` → `battle`。
7. 不要在 `bgmFreeRoam()` 添加 `if (sceneBgmType) return`。剧情 BGM 的隔离依靠 `S.freeRoam === false`；该守卫会让自由探索恢复时错误沿用上一首曲目。

## 演出、UI 与状态规范

- 背景由 `setBG()` 进行渐隐、切换、渐显；CG 使用 `cgShow()` / `cgHide()`，连续同图不应重复闪烁。
- `空格` / `Enter` 能关闭系统弹窗与面板，并推进 CG；修改交互时不得破坏快捷键。
- 剧情对话框高度为 3–4 行，自由探索为 2 行；超出空间的文本必须拆分。
- 对话框紧贴底部行动栏；大型立绘下沿应与对话框上沿对齐。
- 系统、状态、属性信息必须经真实 UI（HUD 或 `sysPopup`）展示，不能在剧情 `text` 中伪造面板文字。
- 所有状态面板正文必须调用 `statusPanelHTML()`；不得硬编码等级、生命、魔力、攻击等会随玩家状态变化的数值。
- 背景亮度设置只影响背景，不能触发 BGM 淡入淡出。

## 提交前检查

1. 新增代码与资源均已纳入版本控制，尤其检查 `assets/cg/`、`assets/bg/`、`assets/portraits/`、`Music/` 与 `tests/`。
2. 执行 `git status --short`，确认没有遗漏的未跟踪文件。
3. 执行 `cd tests && npm test`，处理所有回归失败后再提交。
4. 提交后再次确认工作区干净，并核对远程分支已同步。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 背景不显示 | `bg` 是否包含有效的 `bg-img-*` 类；`loc` 是否为合法 key |
| 新场景没有音乐 | 是否显式设置 `bgm`；音乐类型、映射与文件是否存在 |
| 场景音乐被探索音乐覆盖 | `S.freeRoam` 是否在剧情期间为 `false`；勿在 `bgmFreeRoam()` 加 `sceneBgmType` 守卫 |
| 立绘变成占位样式 | 文件命名与 `PORTRAIT_FILES`、`CHARS`、`CSS_CHARS` 登记是否完整 |
| 人物在对话中跳位或消失 | 是否使用稳定 `DUO()`；旁白和插话是否错误使用单角色 `N()` |
| 状态面板数值不一致 | 是否通过 `statusPanelHTML()` 实时渲染，而非硬编码数值 |
| 多个到期剧情被拆开 | 是否用同一个 `runSceneQueue()` 顺序衔接 |
